# Project Name

NorthStar

The name is temporary and may change in future iterations.

Focus on the product vision rather than the brand name.

---

# Project Vision

NorthStar is an open-source intelligence and discovery platform for digital resources.

The platform helps users collect, organize, discover, connect, preserve, and explore valuable resources through a structured and searchable knowledge graph.

NorthStar is not a directory.

NorthStar is not a bookmarking application.

NorthStar is not a link repository.

NorthStar is a Resource Intelligence Platform.

---

# The Problem

Every day people discover valuable resources through:

- WhatsApp groups
- Telegram channels
- Discord communities
- Slack workspaces
- LinkedIn posts
- GitHub repositories
- Newsletters
- Blogs
- Online communities

Examples include:

- GitHub repositories
- AI platforms
- Developer tools
- Cybersecurity solutions
- SaaS products
- Design resources
- Startup accelerators
- Incubators
- Learning platforms
- Research tools

These discoveries quickly disappear into message history and become difficult to find later.

Most people remember that they saw a resource but cannot remember:

- Where they saw it
- What it was called
- How it related to other tools

The result is fragmented knowledge and repeated discovery effort.

---

# Mission

Build a community-driven platform that transforms scattered discoveries into structured, searchable, interconnected knowledge.

---

# Long-Term Vision

Create the world's most valuable open-source resource intelligence network.

A place where users can:

- Discover resources
- Understand resources
- Compare resources
- Connect resources
- Explore ecosystems
- Build collections
- Contribute knowledge

The platform should evolve into a knowledge graph representing the relationships between digital products, tools, platforms, companies, communities, and ecosystems.

---

# Core Objectives

1. Create a searchable knowledge database.
2. Enable intelligent resource discovery.
3. Support community contributions.
4. Prevent duplicate entries.
5. Store rich metadata.
6. Support advanced filtering.
7. Remain fully open source.
8. Allow public access without mandatory registration.
9. Provide a frictionless onboarding experience.
10. Build a relationship-based knowledge graph.
11. Preserve knowledge that would otherwise disappear in community history.
12. Enable exploration through connections rather than only search.

---

# Core Philosophy

Resources are not links.

Resources are knowledge entities.

Every resource should be treated as an object with:

- Identity
- Metadata
- Categories
- Tags
- Relationships
- Community signals
- Historical context

---

# Knowledge Graph Philosophy

Every resource should be represented as a node.

Relationships should be represented as edges.

Examples:

GitHub
→ Alternative To → GitLab

Notion
→ Competitor Of → Confluence

Slack
→ Integrates With → Jira

OpenAI
→ Built By → Organization

Accelerator
→ Funded → Startup

The relationship layer must become one of the platform's primary differentiators.
